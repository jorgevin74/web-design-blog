Live Blog Site : Project 3

Inspiration:

How we first started to brainstorm ideas was that all four of us created a Discord group chat and chose a day when we would be all available together. Once we got together, we created a Figma page to brainstorm any ideas we had. We originally thought of a map-style page, but then we decided on the tree idea. We then kept thinking of different trees in pieces of media we know that we want to make a reference for the tree. One of them was the very big tree at the end of ‘Attack on Titan,’ and the other was the big tree from Avatar (haven’t seen it lol). By then, we came up with the theme, which was an Alien Futuristic theme that we wanted to have at the beginning of our project. The way the original tree idea came up was because I looked through Week 10 of the class notes, looked at the references, and saw this website here: plants I've eaten. What this website was is a Phylogeny of plants that the user has eaten, and it branches out from different plants and such. We took that idea of a Phylogeny and then decided to flip it to our own idea, and then made it so that every time a user would add a comment or an image, the tree would keep on growing with said images or text. This, of course, was the first draft of an idea of a project we had, and over time, the concept changed as we experimented with different layouts.

Sketches:

Before working on VSCode and creating the basic structure of our website. We decided to create a Figma document detailing our research process and the layout of our brainstorming, from inspiration to sketches. Our only sketches that we made are really on the Figma document. Before drawing the actual tree itself and how it would look on our page, we decided to find what kind of color palette we want the website to have, and we went back to the inspiration, and most of the sketches have a purple to blueish range. Most of used Google to find any inspiration for the colors, but then we also used Coolors.co to fully grab the colors that we wanted. Next, we wanted an idea as to what font we wanted to use or have the website use. The idea that we had was that we wanted to have a futuristic font and also a font that isn’t really decipherable, mainly texts like hieroglyphics and illegible text, to fully emphasize the idea of communication and that anyone can add their piece of text and truly deliver a message to others that they may not understand, but it’s there. Then we decided to finally draw the tree. The way we did it was that we had multiple ways of how we wanted the navigation bar, the home button, and, if needed, an about page, detailing how the website works and what the user can do (this has now changed to an about pop-up). We then came up and drew multiple trees and ideas of how the web page would look. Once the ideas were settled in, we had our class the day after, and we got feedback on how we wanted the page to look and eventually began the technical process.

Technical Process:

Originally, there were concepts of us debating between making the website in 2D, which would be regular HTML, CSS & Javascript and then there was also an ambitious idea to incorporate 3D instead. We then went for the 3D layout after having a group office hour meeting with the professor to get an intro to Three.js and see if it was possible to bring our vision to life. After the meeting, we decided to go with the 3D route. Although challenging, we pushed through and developed a draft or an idea of what the webpage could look like before we asked for feedback in the second-to-last class of the semester. One of the things that I thought was going to be difficult was checking how many people visited our web page and who was currently there, and leaving, but with Socket.io, it was helpful and easy to put the pieces together.

Resources:

One of the main resources that we used was actually GitHub, more specifically, the week 11 notes on installing Socket.io. It helped us set up Socket.io and was our base layout for the project. It also helped us initialize our server and helped us check and see how many users have connected to our website and how many have left. This was the base layout, and as we continued, we expanded and eventually made it so that the user can see other users who are also interacting with the web page and who leave.

What I worked on:

So coming into this, I decided to work on the backend portion of the page alongside Kris (and if we wanted to help out with the front end, we could do so and vice versa). Starting, we eventually created the server.js page with the necessities it needed. I then decided to add the about “page, which then got turned into something different, more like a pop-up instead of a page, so that got removed and switched to something else that I also worked on. After that, I decided to install socket.io and get that up and running. What was difficult was that I followed the instructions on how to set it up completely and added some stuff to determine if the user had connected to the site or if they left, and it wasn’t working. I was lucky enough to receive help from the professor in the second-to-last class, which helped us adjust the error, which was that socket.io needed the server name to be connected to the localhost instead of the app, so normally we would do {app}.listen and then include the server port we would be using. What I didn’t realize was that it needed the {serverName}.listen for it to work, and once we got that sorted, then socket.io started working. So to summarize for this portion, installed socket.io and added it to the header of the Nunjucks page to get it started, and imported its library as well as making sure it’s receiving but also sending a message back to the user, which it did after the troubleshooting. After that was done, I decided to work on the front end for a bit and work on the about page (not really an official page, more like a pop-up). What it would entail would just be an explanation of how our site works and how users can maneuver through the site.
